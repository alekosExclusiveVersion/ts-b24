API Parts-Catalogs (PC): чем отличается /schemas от /groups-tree

Источник: официальная OpenAPI-спецификация https://api.parts-catalogs.com/v1 (Catalogs API v1.18.0) + практическая проверка. Дата: 09.09.2026.

Контекст: заявка #113524 — «не работает API китайских каталогов» (клиент [3917] tsk-market.kz, сервер kz1, АИ 2.0 v6.72.159). Ниже — детальный разбор двух GET-эндпоинтов и план проверки причины.

1. Общее

Оба эндпоинта находятся в теге Groups tree и отвечают на «навигацию по каталогу», но решают разные задачи. Детали (список позиций на схеме с координатами) получаются через GET /catalogs/{catalogId}/parts2.

2. GET /catalogs/{catalogId}/schemas

operationId: Get schemas — «Get schemas that lead to detail pages» (схемы, ведущие к страницам деталей).

ПараметрТипОбязательныйОписание
catalogIdpathдаID каталога (toyota, bmw, …)
carIdqueryдаID автомобиля
branchIdqueryнетФильтр по ветке (= id группы)
criteriaqueryнетСтрока фильтра (из /car/info)
pagequeryнетНомер страницы; максимум 24 элемента на ответ (default 0)
partNameIdsqueryнетID имён деталей для фильтра (пример 56,85)
partNamequeryнетИмя детали для фильтра (пример «Air filter»)

Ответ 200: SchemasResponse { group: Group|null, list: Schema[] }, заголовок X-Total-Count — общее число доступных.

Schema {
  groupId:     string            // id группы
  img:         string|null       // картинка схемы, напр. //img.parts-catalogs.com/toyota_2022_12/usa/84E429B.png
  name:        string            // "ENGINE & TRANSMISSION ILLUST NO. 1 OF 7"
  description: string|null
  partNames:   [{ id, name }]    // имена деталей схемы
}

Назначение: плоский список «чертежей» узлов (тойотовский тип иллюстраций) с пагинацией и фильтрами; каждый элемент — вход в страницу деталей.

3. GET /catalogs/{catalogId}/groups-tree

operationId: Get groups tree — «Get groups tree».

ПараметрТипОбязательныйОписание
catalogIdpathдаID каталога
carIdqueryнетID автомобиля (опционально)
criteriaqueryнетСтрока фильтра
cachedquery boolнетtrue — общее нефильтрованное дерево из кэша; иначе фильтрованное дерево с повышенной задержкой

Ответ 200: Array<GroupsTreeResponse> — рекурсивное дерево всей структуры групп:

GroupsTreeResponse / GroupsTree {
  id:        string|null  // id группы
  name:      string
  parentId:  string|null
  subGroups: [GroupsTree] // вложенные подгруппы
}

Назначение: полное вложенное дерево групп (категорий) за один запрос, без пагинации; дальнейшая навигация выполняется локально по subGroups.

Общее: оба — «поиск пути к деталям», оба не содержат самих деталей; детали и полная иллюстрация с координатами — только через /parts2. Для грузовых каталогов в спецификации предупреждение: «Attention! You must use the groups2 and parts2 methods for truck catalogs» — дерево групп для грузовиков не использовать.

5. Практическая проверка (09.09.2026)

ЗапросРезультат
GET /ip (без ключа)200 {"ip":"2.27.27.160"}
GET /catalogs c заголовком ApiKey401 "Unauthorized" — неверный заголовок авторизации
GET /catalogs c заголовком Authorization: <ключ>403 {"code":403,"errorCode":1003,"message":"IP 2.27.27.160 not allowed"}

Вывод из практики: ключ PC (TWS-…) принимается только через заголовок Authorization (в спецификации securitySchemes.ApiKey = name: Authorization), а не через заголовок ApiKey. Ключ привязан к белому списку IP — текущий адрес 2.27.27.160 в него не входит, поэтому данные не отданы.

6. Связь с инцидентом #113524

Для проверки причины «не работает API китайских каталогов» у tsk-market.kz необходимо:

  1. Определить, каким эндпоинтом пользуется интеграция: /groups-tree (навигация по группам) либо /schemas (иллюстрации узлов) — по GET-запросам клиента из вложения (fileId 1914463).
  2. Проверить ответ API PC: возможные сценарии:
    • 403 IP not allowed — сервер kz1 (или боевой IP клиента) не в allow-list ключа / IP сменился;
    • 401 — неверный формат ключа (передача в заголовке ApiKey вместо Authorization, либо неверный/истёкший TWS-ключ);
    • 400/422 — некорректный carId/groupId/branchId в запросе;
    • — лимиты/изменение версии API (v1.18.0).
  3. Прогнать реальные GET-запросы из вложения клиента с IP, разрешённого для ключа.

7. Соответствие эндпоинтов визуальной части (проверено по фронтенду)

Виджет каталога на сайте клиента (пример: http://test-ar6.auto-vision.ru/cats/#/catalogs?catalogId=audi) подключает https://ru.gui.parts-catalogs.com/v3/parts-catalogs.js → модуль connect-catalogs_*.js → bundle_cd5b3708.js (обычный) или bundle-ai.js (UA AI ...). Разбор кода бандлов показывает реальные вызовы API:

Экран/блок визуальной частиВызываемый эндпоинтПараметры
Выбор каталога, модели, автоGET /catalogs/, /catalogs/{id}/models/, /cars2—
Список групп (навигация по уровням)GET /catalogs/{id}/groups2/
заголовок X-Redirect-Template → ссылки #/schemas?...&branchId=%groupId% и #/parts?...&groupId=%groupId%		carId, groupId, criteria
Дерево групп в сайдбаре/панелиGET /catalogs/{id}/groups-tree/ — всегда с cached:1 (кэшированное нефильтрованное дерево)carId, criteria, cached:1
Страница схем (иллюстраций узлов) #/schemasGET /catalogs/{id}/schemascarId (обяз.), branchId, page
Страница позиций/деталей #/partsGET /catalogs/{id}/parts2carId, groupId

Наблюдения из кода виджета:

  • Флаг cached фронт выставляет через обёртку ha(e){return{...e,cached:1}} — дерево всегда берётся из кэша (spec: «general unfiltered group tree from cache»), а не «filtered tree with increased latency».
  • Getter groupsTreeAvailable берётся из флага модели (t.groupsTreeAvailable) — дерево доступно не для всех каталогов; при недоступности обращение остаётся к groups2.
  • /schemas — отдельный экран-сетка картинок узлов с переходом на детали (#/parts) — ровно как в спецификации «Get schemas that lead to detail pages».
  • Значит для неработоспособности «китайских каталогов» виджет вызывает либо groups2+groups-tree (навигация), либо schemas+parts2 (выбор узла/детали) — по каким именно из них сыпется, покажет содержимое вложения (GET-запросы клиента).
